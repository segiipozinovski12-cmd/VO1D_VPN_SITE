# VO1D VPN — Windows

Нативное приложение для Windows 10/11 x64 на WPF / .NET 8. Интерфейс перенесён
из актуальной `main/ios/VO1DVPN` и адаптирован к широкому окну компьютера.

## Запуск

1. Откройте `VO1D_VPN.exe` и разрешите запрос Windows на права администратора:
   они нужны для виртуального сетевого адаптера и маршрутов.
2. Вставьте полную строку `VO1D1.<адрес-API-в-base64url>.<ключ>` либо VPN-ссылку.
   Можно вставить обычный `VOID-…`, предварительно указав HTTPS-адрес API.
3. Выберите локацию и нажмите кнопку питания. Статус «Подключено» появляется
   только после передачи данных через VPN и проверки системного маршрута.

Ничего отдельно устанавливать не нужно: .NET, VPN-ядро, Wintun и библиотека
Kill Switch упакованы в исполняемый файл. При первом подключении ядро
извлекается в защищённый каталог `Program Files/VO1D_VPN/runtime/1.14.2`.
Сессия и импортированные VPN-ссылки хранятся через Windows DPAPI.

Имеющиеся 12-символьные лицензии backend привязаны к одному устройству.
Использованная на iPhone лицензия вернёт `key_in_use` на Windows; необходим
отдельный ключ или собственная VPN-ссылка. Эта версия не меняет backend,
не обходит привязку лицензии и не выдаёт подписки сама.

В репозитории отсутствует рабочий адрес API: он задаётся полной строкой
активации или полем адреса. В приложение не встроены чужие VPN-ключи.

## Подключение

- VLESS TCP/REALITY/TLS, WebSocket, gRPC, HTTP/H2, HTTPUpgrade;
- VMess, Trojan, Shadowsocks без плагинов, Hysteria2;
- виртуальный TUN с IPv4/IPv6 и DNS over HTTPS через VPN;
- до четырёх попыток маршрутов из `/api/app/tunnel?attempt=…&stealth=…`;
- реальные TCP-пинги, статистика трафика и проверенный внешний IP;
- динамический WFP Kill Switch блокирует выход других процессов через
  физические интерфейсы, если ядро падает, пока VO1D открыт;
- явное отключение/выход снимают защиту и восстанавливают маршруты;
- минимизация в системный трей, избранное, поиск, профиль, автоподключение;
- сеть API не удаляет сохранённую сессию при временном сбое.

VLESS без TLS/REALITY и ссылки, отключающие проверку сертификатов, отвергаются.
XHTTP, KCP, VLESS Encryption и Shadowsocks-плагины пока не поддерживаются:
при наличии других маршрутов приложение пробует следующий.

Kill Switch работает в течение жизни приложения. При аварии самого GUI
динамические фильтры WFP удаляются Windows; постоянной защиты после закрытия
или до входа в систему эта версия не обещает. Параметры подключения
применяются при следующем подключении. Проверка в CI использует собственный
локальный VLESS-сервер: она не доказывает доступность production-серверов.

## Сборка

Windows, .NET SDK 8, Python 3, Visual Studio Build Tools с C++ Windows SDK:

```powershell
python windows/scripts/fetch_runtime.py
# Выполнять следующую команду в x64 Native Tools Command Prompt:
cl /nologo /O2 /MT /LD /EHsc windows/native/guard.cpp /link /OUT:windows/VO1D.Vpn/Assets/runtime/vo1d-guard.dll
dotnet publish windows/VO1D.Vpn -c Release -r win-x64 --self-contained true -o windows/dist
```

GitHub Actions `.github/workflows/windows-vpn.yml` собирает самостоятельный
`.exe`, проверяет конфигурации настоящим ядром, запускает приложение на Windows
и проверяет передачу данных через TUN, IPv6-маршрут, блокировку обхода,
падение ядра и восстановление сети. Отчёты и снимки реальных WPF-окон
публикуются отдельным артефактом. Тестовые экраны обозначают маршрут как TEST.
